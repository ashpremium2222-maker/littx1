## Legacy exposure and future cutoff requirements

Short ticket IDs continue to authorize legacy view, PDF download and resend. The public ticket view screen still calls the legacy API. New emails and selected in-app controls use OTP recovery, but existing email/WhatsApp messages and saved PDFs cannot be recalled. Optional WhatsApp PDF delivery still depends on the public download route because providers fetch a URL and the current secure token contract requires an Authorization header. External client/provider-template inventory is incomplete.

Before any cutoff, require: all protected replacement workflows verified in staging; a secure provider-fetch capability for optional WhatsApp PDF attachments or a tested alternative; customer recovery for online, seller and PR tickets; role-scope and suspension checks; old-link compatibility tests; individual and group ticket gate scans using existing IDs/QRs; customer communication and support recovery for mailbox loss; and a separately approved cutoff date. Do not rotate IDs or QR payloads. Do not use short IDs alone as an exception for mailbox-loss recovery.

## Release decision

**Production remains NO-GO.** Local test/build/type/audit results are necessary but insufficient. Change the recommendation only after all staging-blocked tests above have PASS evidence from isolated staging resources, actual provider deliveries are confirmed, Mongo indexes/TTL and cross-instance limits are observed, staff authorization is exercised across roles, and the legacy-link migration plan is ready. A later cutoff still requires a separately approved date; Phase 12 did not set one.
