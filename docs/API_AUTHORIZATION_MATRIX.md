# Stageway API Authorization Matrix

Updated 2026-10-20 for Phase 11. This inventories active API route declarations in staging/server/server.js, along with shared middleware and sensitive database operations. Customer booking history uses OTP recovery and purpose-bound short-lived access tokens. Legacy short-ID routes remain active during the approved transition and remain a release blocker.

## Shared middleware and session controls

- CORS permits origins from CORS_ORIGINS and configured BASE_URL; localhost origins are allowed only outside production. Requests without Origin support native/server clients. Credentialed CORS is disabled.
- JSON request bodies are limited to 256 KiB. Razorpay webhook handling retains raw request bytes for HMAC checks. Security headers include content-type, frame, referrer, permissions policy, and production HSTS.
- API database middleware waits for configured MongoDB; it does not authenticate. The final error middleware emits generic production responses.
- requireMasterAdmin accepts a configured ADMIN_KEY header or a persisted master_admin session. requireAdmin accepts master_admin/company_admin; company admin sales are scoped. requireApprovalAdmin permits master admins and Littlane company admins for owned sales. Seller, PR, and Shadow sessions are persisted, revocable, and expire after 12 hours; scanner sessions are signed and expire after 12 hours.
- Sensitive login, checkout, ticket, and recovery route limits use the shared MongoDB-backed rate-limit collection and fail closed if it is unavailable.
- PDFs are not served from a public static directory. Legacy `/api/ticket/:ticketId` view/download/resend routes still treat the short ID as bearer authorization during the approved compatibility period. OTP recovery returns ticket/email-bound tokens with separate view, PDF, and resend purposes.

## Coverage limits and remaining risks

- Tests cover unauthenticated protected routes, insufficient and expired sessions, scanner event assignment, invalid Razorpay signature, duplicate atomic order claim, and untrusted CORS. Customer booking ownership, all tenant checks, WebAuthn replay, ticket status transitions, production origin deployment, and live Razorpay replay need more integration coverage.
- No customer login, password reset, booking-owner lookup, or customer logout exists. Existing short ticket IDs remain bearer credentials and need customer-safe rotation; new tickets use 122-bit UUID entropy.
- Per-process rate limits can be bypassed across serverless instances; add shared gateway/store throttling before high-volume public deployment.
- No refund or settlement API is declared. UI/model refund fields do not prove gateway refund behavior. No live payment or refund was executed.
- Per-event seller assignments are not modeled across all legacy endpoints. Define a first-class assignment model before multi-event work.
- Dependency scanning, provider-backed webhook replay, backup/restore, and Android SDK build remain unverified.
